# time-key-vectors.json

Cross-language fixture for time values (`docs/time.md`) and the `key` format
(`docs/key-spec.md`). Generated by `psio_time_key_conformance_emit`
(`cpp/tests/time_key_conformance_emit.cpp`); `ctest` fails if the checked-in
file is not what the C++ implementation generates. Consumed by
`cpp/tests/time_key_conformance_tests.cpp`,
`rust/psio/tests/time_key_conformance.rs` and
`js/src/test/time-key-conformance.test.ts`.

```
{ "version": 1,
  "schema_ir": hex of pssz(Schema) holding every type under its id,
  "types":   [ { "id", "composite" } ],
  "vectors": [ row ] }
```

All byte strings are lower-case hex. A value is identified by its PSSZ
(automatic profile) encoding. Rows, by `kind`:

| kind | fields | meaning |
|---|---|---|
| `value` | `type`, `pssz`, `key`, `json`?, `ijson`? | the value encodes to `key`; to `json` / `ijson`, which read back as the value. `json` and `ijson` are absent when the value has no text (a time point outside years 0000..9999, a NaN): writing text must fail. A NaN value is identified by its bits: the key decodes to a value with the same PSSZ bytes |
| `text-accept` | `type`, `text`, `pssz`, `json` | the JSON document `text` reads, under json and under ijson, as the value `pssz`; `json` is that value's canonical text |
| `text-reject` | `type`, `text` | `text` is rejected under json and under ijson |
| `key-reject` | `type`, `key` | the bytes are not a key of `type` |
| `key-order` | `type`, `values` | values (pssz) in strictly ascending value order; their keys are strictly ascending bytewise |
| `key-order-bits` | `type`, `values` | values (pssz) in strictly ascending **key** order where the language's `<` has no answer (NaNs, `docs/key-spec.md` §4): their keys are strictly ascending bytewise, and each key decodes to a value with exactly the same PSSZ bytes |
| `key-prefix` | `type`, `pssz`, `count`, `prefix`, `bound` | `prefix` is the key of the first `count` elements of the composite value; `bound` is its exclusive upper bound, `null` for none |
| `bound` | `prefix`, `bound` | the exclusive upper bound of the raw bytes `prefix` (`type` is `"bytes"`) |
| `key-invariant` | `type`, `key`, `pssz`, `reason` | `key` is the key, and `pssz` the encoding, of a value of `type`'s wire type that violates an invariant of `type` (message `reason`). The typed key readers (validate, decode) and the typed pssz validator reject them with `reason`, and no typed key writer writes the value; a reader that knows only the wire type (a schema with no handler) decodes `key` to the value `pssz` |

Type ids: `time_point<unit>` / `duration<unit>` / `monotonic<unit>` are 64-bit
signed; `time_point<seconds,u32>`, `duration<60/1,i32>` and
`monotonic<millis,u32>` name their tick type. `monotonic<...>` is a monotonic
time point (Schema IR id `monotonic-<unit>`): its text is the tick count.
`Timer` is `{expires: monotonic<micros>, started:
optional<monotonic<seconds>>, laps: list<monotonic<millis,u32>>}`.
`Stamps` is a fixed-layout record `{created: time_point<seconds>, updated:
time_point<micros>, ttl: duration<millis>, legacy: time_point<seconds,u32>}`;
`Event` is `{name: string, at: time_point<millis>, precise:
optional<time_point<nanos>>, history: list<time_point<seconds>>, elapsed:
duration<nanos>, timeout: duration<60/1,i32>}`; `Account` is `{shard: u32,
owner: string, seq: optional<i64>}`. `string` is a raw string (Schema IR id `string`) and holds UTF-8 in every vector;
`bytes` is a list of u8.

`Id`, `Blob`, `Endpoint`, `Ratio`, `Ref`, `Name`, `DerKey`, `Range`, `Level`
are the transparent wrappers and custom types of `custom-types.md`;
`ShardKey` is a transparent wrapper of `tuple<u32,string>` (a composite key:
its `key-prefix` rows are the tuple's). A key is the key of the wire type —
a text form plays no part, an invariant does. The `value` rows of the types
with a custom text form (`Blob`, `Endpoint`, `Ratio`, `Ref`) carry the typed
text: a schema-driven codec reproduces it with the type's handler.
