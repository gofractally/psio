# evolution-vectors.json

Pairs of types (and of interfaces) of two Schema IRs, with the verdict of the
run-time schema comparison for each: may the new one replace the old one
(`evolves_from`), and are the two the same type (`equivalent`)? The rules are
`docs/pssz-spec.md` §7.5 / §7.6 / §16; what exactly is compared is stated in
`cpp/include/psio/pssz_ir_compare.hpp` and `docs/pssz-ir-runtime.md`
("Comparing schemas at run time").

Generated by `psio_evolution_conformance_emit`
(`cpp/tests/evolution_conformance_emit.cpp`, types in
`cpp/tests/evolution_conformance_types.hpp`); `ctest` fails when the file is
not what the implementation generates, and the emitter refuses to write a row
whose `wire` verdict differs from the compile-time
`psio::pssz_evolves_from<Old, New>` for the same two C++ types.

```json
{ "version": 1,
  "schemas":    [ {"id": "record-append-optional/old", "ir_hex": "…"}, … ],
  "types":      [ {"name": "record-append-optional",
                   "old_schema": "record-append-optional/old", "old_type": "Root",
                   "new_schema": "record-append-optional/new", "new_type": "Root",
                   "evolves":    {"wire": V, "contract": V},
                   "equivalent": {"wire": V, "contract": V}}, … ],
  "interfaces": [ {"name": "interface-grown",
                   "old_schema": "…", "old_interface": "svc",
                   "new_schema": "…", "new_interface": "svc",
                   "evolves": {…}, "equivalent": {…}}, … ] }
```

- `schemas[].ir_hex` is the PSSZ encoding of a `psio::Schema` (lowercase hex),
  the form of `schema_ir` in the other fixtures.
- `old_type` / `new_type` name a member of that schema's `types`;
  `old_interface` / `new_interface` name a member of its `interfaces`.
- A verdict `V` is `{"ok": true, "code": "", "path": ""}` or
  `{"ok": false, "code": "<rule>", "path": "<where>"}`: the **first** rule
  broken, in the order the reference walks (below). The sentence a library
  reports beside it is not part of the fixture.
- `wire` / `contract` are the two things a comparison can be asked for:
  `wire` is the bytes and which bytes are values; `contract` (the default in
  C++) adds what a consumer of the text forms and of the type's identity sees
  — member and alternative names, custom ids, enums, the text shape of a
  record, `jsonInt` / `ijsonInt`, `ijsonName`.
- Every pair appears in both directions: `name` and `name~reverse`.

## Codes

| code | rule |
|---|---|
| `malformed-schema` | a schema is not well-formed, or names a type it does not have |
| `type-changed` | another kind of node: integer, float, bool, string, bytes, bit vector, bit list, list, array, optional, variant, record, map, set, nested value |
| `boxed-changed` | `Custom{…, "box"}` on one side only |
| `custom-id-changed` | contract: the custom ids on the way to the wire type differ |
| `enum-changed` | contract: an `Enum` on one side only; an enumerator removed or renumbered (`equivalent`: any difference) |
| `integer-changed`, `float-changed`, `bit-count-changed`, `array-length-changed`, `fixed-size-changed` | as named |
| `utf8-changed` | a raw string against a UTF-8 string |
| `optional-form-changed` | an optional with a selector byte against one without |
| `bound-tightened` | `evolves`: New's `[min, max]` does not contain Old's |
| `bound-changed` | `equivalent`: the two ranges differ |
| `width-changed` | an offset width differs (a record, a tuple, a list / array / map / set of variable-size elements, a map entry) |
| `key-type-changed` | the key type of a map / element type of a set is not equivalent |
| `alternatives-removed`, `alternative-count-changed` (`equivalent`), `alternative-renamed` (contract) | variants |
| `dwnc-changed`, `fields-removed`, `field-count-changed` (`equivalent`), `dwnc-gained-fields`, `field-renamed` (contract), `appended-field-not-optional` | records, tuples, argument lists |
| `max-dynamic-data`, `max-fields` | caps (§16) |
| `text-form-changed` | contract: an object against a named or positional argument list; `jsonInt` / `ijsonInt`; an alternative's `ijsonName` |
| `result-changed` | a function result on one side only |
| `function-removed`, `function-added` (`equivalent`), `type-removed`, `type-added` (`equivalent`) | interfaces |
| `interface-removed`, `interface-added` (`equivalent`) | whole schemas |

## Paths

From the root: `.field` (a record member, by name; by index for a tuple or a
positional argument list), `[]` (the element of a list, array or set; the key
and the mapped value of a map are `[].0` and `[].1`), `?` (the payload of an
optional), `<Alt>` (a variant alternative, by its member name), `(nested)`
(the inner type of a nested value). The root itself is `(root)`. For an
interface the path starts with the function name and `(args)` or `(result)`
(`transfer(args).amount`), or with `type:Name` for a listed type; for a whole
schema, with the interface name and `/`.

A rule about a record as a whole (a field count, a renamed field, a cap, its
width) is reported at the record, not at a member.

## The order of the walk

At each pair of nodes, after following named aliases and taking off the
nodes that add nothing to the bytes (`Enum`, custom ids that are not part of
the binary form):

1. `boxed-changed`; contract: `custom-id-changed`, `enum-changed`;
2. a pair already being compared (a recursive type) is accepted;
3. `type-changed` (a lone `char` is the integer `u8`; a `Tuple` and an
   `Object` are both records; a `Struct` is a `definitionWillNotChange`
   record);
4. by kind:
   - string / bytes: `utf8-changed`, `fixed-size-changed`, then the range
     (the element type of the byte container is not compared);
   - nested: the range of the member bound, then the inner types as a root of
     their own (no cap or bound reaches them);
   - optional: `optional-form-changed`, then the payloads at the same
     position (the member's bound and the cap reach them);
   - list: the range; array: `array-length-changed`; then, when the elements
     are not fixed-size on both sides, `width-changed`; then the elements;
   - map / set: the range, `width-changed`, the key types (compared as
     `equivalent` in both relations: `key-type-changed`), then for a map the
     width of the entry tuple and the mapped values;
   - variant: the count, then per old alternative: contract
     `alternative-renamed`, the types, contract `text-form-changed`
     (`ijsonName`);
   - record: `fixed-size-changed`, `dwnc-changed`, contract
     `text-form-changed` (text shape), the count (`field-count-changed`,
     `fields-removed`, `dwnc-gained-fields`), `width-changed`, then per old
     member: contract `field-renamed` and `jsonInt` / `ijsonInt`, the types;
     then `appended-field-not-optional`, `max-dynamic-data`, `max-fields`.

A position is the cap of the nearest enclosing record that has one (reset by
a record without one and by a nested value; passed through lists, optionals,
variants and `Tuple` nodes) and the `lengthBound` of the member holding it
(passed through optionals only). Widths are derived at that position exactly
as the codec derives them.

## Rows that are not two C++ declarations

`byte-list-char-element` (the `Custom{List<Custom{u8,"char"}>,"hex"}` of
older schemas against `Custom{List<u8>,"hex"}`: one type,
`docs/spec-evolution-notes.md` E-011), `bound-in-type-or-on-member`
(`BoundedList<u32, 8>` against a `List<u32>` member with
`lengthBound = "max=8"`: one type), `boxed-member` and `recursive-append`
are built or edited as IR.
