# Variant label fixture

`variant-label-vectors.json` pins **the label of a variant alternative**,
for every language: which name each alternative has, that the Schema IR
names the alternative by it, and that the tagged text form is keyed by it.
It is generated by `psio_variant_label_conformance_emit`
(`cpp/tests/variant_label_conformance_emit.cpp`, from the declarations in
`cpp/tests/variant_label_conformance_types.hpp`); the ctest
`psio_variant_label_conformance_regen` fails if the checked-in file is not
what the C++ implementation generates. Regenerate with

```sh
<build>/cpp/tests/psio_variant_label_conformance_emit conformance/variant-label-vectors.json
```

## The rule

An alternative has one label (`docs/annotations.md`, "Variant alternative
labels"):

1. the name the declaration gives the alternative, where the language names
   alternatives (a Rust enum variant's identifier, the key of a TypeScript
   `variant({...})`);
2. else the name of the alternative's type (a C++ `std::variant`, a Python
   `Union`): a reflected type's name, and for a type without a declared
   name `bool`, `int8` … `uint64`, `int128`, `uint128`, `float32`,
   `double`, `string`, `T[]`, `T[N]`, `T?`, `tuple_A_B`, `map_K_V`,
   `set_K`, `variant_A_B`;
3. else its position (`"0"`, `"1"`, …): a type with no name, and a type
   name two alternatives of the variant share.

A language's annotation states a label instead (C++
`psio::variant_labels<V>`, Rust `#[psio(name = "…")]`, Python
`psio.alt("…")`; in TypeScript the key is the label). The implementing
language is the naming authority: a twin states the labels it would not
derive itself.

Labels are not on the wire of a binary format: the PSSZ of a variant is its
selector (the alternative's position) and the alternative.

## The declarations

```
record Circle { radius: u32 }      record Square { side: u32 }

Records  = variant<Circle, Square>                       Circle, Square
Scalars  = variant<bool, u8, i16, u32, i64, u64,         bool, uint8, int16, uint32, int64,
                   f32, f64, raw string>                  uint64, float32, double, string
Generic  = variant<list<u32>, optional<u32>,             uint32[], uint32?,
                   tuple<u32, raw string>, array<u16, 2>, tuple_uint32_string, uint16[2],
                   list<Circle>, bytes>                   Circle[], uint8[]
Repeated = variant<u32, raw string, raw string, Circle>  uint32, 1, 2, Circle
Stated   = variant<Circle, Square, u32>                  circle, square, side   (stated)
```

`declaration` in the fixture is the C++ text (for readers; nothing parses
it). An implementation declares the same variants in its own syntax — a
Rust enum states every label that is not its variant's identifier, a
TypeScript `variant` uses the labels as keys.

## Format

```
{ "version": 1,
  "declaration": [ "...", ... ],
  "schema_ir":   "<hex of pssz(Schema)>",
  "schema_json": "<the psio::json text of the same Schema>",
  "variants": [ { "name", "labels": [ ... ] } ],
  "vectors":  [ { "name", "type", "index", "label", "pssz", "json", "ijson" } ] }
```

**`schema_ir`** is what `SchemaBuilder` builds by inserting the five
variants under their names, in the order above
(`builder.insert<Records>("Records")`, …). Each is a `Variant` whose
`members[i].name` is the label and whose members carry **no attributes**:
the IR has no second name for an alternative (there is no `ijsonName`).

**`variants`** restates the labels, in alternative order.

## Rows

One value per alternative (two for the optional). Every implementation
must, typed and schema-driven (root: the variant's name in `schema_ir`):

- encode the value to exactly `pssz` — the selector byte is `index`;
- write exactly `json` (`[index, value]`: no label) and `ijson`
  (`{"<label>": value}`), and read each back to the same bytes;
- build, from its own declaration, a schema node whose alternatives have
  these labels and no attributes. An implementation whose builder numbers
  anonymous types as C++ does reproduces `schema_ir` byte for byte; one
  whose variants are named types (a Rust enum) is `equivalent` to it under
  `contract`.
